Understanding SQL Injection

A side-by-side demonstration of how SQL injection works, why it works, and how parameterized queries eliminate it entirely.

⚠️

Vulnerable Login

User input is interpolated directly into the SQL string. A single quote character can break out of the string context and inject arbitrary SQL logic — bypassing authentication entirely.

f"...WHERE username = '{username}'"

✅

Secure Login

A parameterized query separates the SQL structure from the data. The database driver compiles the query first, then binds values as literals — making injection structurally impossible.

db.execute("...WHERE username = ?", (username,))

How the attack works

1
The vulnerable app builds its query as: WHERE username = 'INPUT' AND password = 'INPUT'
2
Enter ' OR '1'='1 as the username. The single quote closes the string literal early, injecting OR '1'='1 as SQL logic.
3
The query becomes: WHERE username = '' OR '1'='1' AND password = '...' — '1'='1' is always true, so every row matches.
4
The secure login uses ? placeholders. The same payload is treated as a literal string value, not SQL. No rows match. Access denied.
